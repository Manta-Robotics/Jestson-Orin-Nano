Manta 跟随控制逻辑与修复验收
日期：2026-11-01（北京时间）

一、已确认的参数与行为

1. UWB 方位角数据最大变化速度：45°/秒。本次新增，由用户确认。
2. 船体目标跟随距离：2.5 米。本次从 0.5 米改为 2.5 米，由用户确认。
3. 云台偏航可控区间：−135°～+135°，保持原值。
4. 目标进入后方不可达区：保持进入前所在一侧的限位，重新进入可达区后再跟踪，由用户确认。
5. 船体自动跟随与云台 UWB 跟踪继续分开开启，由用户确认。
6. 云台偏航指令限速仍为原来的 20°/秒。它与新增的 UWB 数据 45°/秒是两个不同参数。
7. 俯仰保持原来的 0° 水平目标；UWB 仰角字段尚未验证，未擅自启用上下跟踪。
8. 原有 XY 输出速度上限仍为 1 米/秒，未增加滤波时间常数或调整控制增益。

二、UWB 公共数据链路

USB 串口完整定位帧
  → 独立采集/计算线程，按 35 Hz 处理最新完整位置帧
  → 现有响应优先 XY 平滑
  → XY 位移速度限制（1 米/秒）与方位角速度限制（45°/秒）
  → 一组一致的距离、方位角、X、Y
  → 同时供船体控制、云台控制、网页和日志使用。

新增角速度限制放在现有平滑输出处，没有只修改网页显示，也没有再叠加一层长时间滤波。
对每次有效输出，用同一单调时钟的时间差限制角度变化：
  最小等价角差 = atan2(sin(新角−旧角), cos(新角−旧角))
  允许角步长 ≤ 45°/秒 × 本次时间差。
例如 +179° 到 −179° 按 2° 处理，而不是 358°。
限制角度后重算 X、Y，并使内部速度与实际输出位移一致；保留原有 XY 速度上限。
重复时间戳不能推动坐标继续移动。断线或数据过期不生成伪造的新鲜定位。

注意：UWB 的 ±180° 是环绕角；云台的 ±135° 是有限转动范围，二者不能使用同一种跨界规则。

三、船体跟随控制

网页单独开启船体自动跟随后，后端按当前配置选择 traditional / relative_imu 路径；
通过飞控连接、UWB/IMU 有效性等现有前提检查，再建立 MANUAL 控制模式和武装状态。
本次维护验收没有启动船体自动推进或解锁螺旋桨。

距离误差为：测得目标距离 − 2.5 米。
当前 relative_imu 路径利用距离误差和距离变化率计算期望接近速度；
结合已有接近、制动约束和相对速度 PI 控制形成油门请求，使用 IMU 偏航/角速度形成转向请求。
direct_control=true 时，它使用公共平滑位置直接导引，不能仅因为 relative_nmpc.enabled=true
就声称每一帧都在运行 NMPC；实际分支还取决于 directControl 和可用路径状态。
GPS/导航条件满足时可启用现有 GPS 速度闭环或路径参考；没有 GPS 时不把油门当作实测绝对速度。
随后通过现有推进映射、油门/转向变化限制和 MAVLink 发送至飞控。

本次也修正了旧控制分支的距离冲突：当目标距离设置在原有近距接近区之外时，
旧的近距“固定向前接近”分支不能再覆盖正常的距离控制。
网页中“目标小于 1.2 米，推进保持停止”的固定提示已移除，避免与新配置不符。

失去 UWB 时，保持原有 last_point_model 策略：
短时可依据最后测得位置和已施加推进量做有界模型接近，超过原有时间/位移等条件后保持中性输出。
模型位置始终标注为估算，不更新真实 UWB 测量时间。
IMU、飞控等其他前提失效仍按现有停止流程处理。
本次没有把丢失标签后的行为擅自改成其他策略。

2.5 米是控制目标，不代表已经完成实船航行并证明实际间距始终等于 2.5 米。
原有距离死区、制动模型、油门增益及其他阈值均保留。

四、云台跟随控制

用户单独开启“UWB 信标”模式
  → 检查公共 UWB 位置与新鲜云台反馈
  → 使用现有安装外参变换得到相机目标方向
  → 处理有限偏航范围
  → 从当前反馈位置开始，按原有 20°/秒限制绝对角指令变化
  → 通过 SIYI SDK 绝对角指令发送给真实 A8
  → 持续读取实际姿态反馈。

当前外参为既有的安装几何：水平同向、UWB 接收中心在云台旋转中心下方 4 cm，
平面分支将 UWB 水平方位映射到云台坐标；俯仰目标保持水平。
没有重新拟合或擅自改变安装符号、角度比例和偏置。

目标仍在 −135°～+135° 内：正常跟踪。
目标进入后方不可达区：保留原侧限位，状态明确显示目标超出范围，不能继续显示为已锁定。
因此目标在后方跨过 ±180° 时，不再让限位目标从 +135° 来回跳到 −135°。
目标从另一侧重新进入可达区后，云台仍需沿合法区间转过去；有限关节不能穿过后方硬限位。
按当前 20°/秒指令上限，270° 合法区间转移本身至少需要约 13.5 秒。

45°/秒 UWB 数据限速不等于云台能以 45°/秒运动；目标变化快于 20°/秒时仍会产生跟踪延迟。
本次没有擅自提高云台转速来掩盖这一约束。

五、网页录像修复

原问题包括：网页在板端确认前就显示正在录像；未同步录制进程失败或结束状态；
停止操作没有等待 FFmpeg close/MP4 封装完成，旧进程退出还可能清除新录制会话。

修复后：
1. 明确区分 starting、recording、stopping、stopped、failed。
2. 收到真实视频帧后才进入 recording，网页不再仅因点击按钮就显示 REC。
3. Socket.IO 和状态轮询同步录制状态，录像状态不会覆盖云台跟踪状态。
4. SIGINT 后等待 FFmpeg 关闭并完成文件封装，再返回停止成功和刷新录像列表。
5. 进程仍未关闭时不能创建下一场录制；同时处理缺少程序、输入错误和无有效帧文件。
6. 后端重启使用新的录制实例标识，旧的状态序号不会压住新后端状态。
7. 有视频但云台控制反馈不可用时，录像按钮不再被云台控制链路的状态一并禁用。

录像继续保存到 Jetson 的 recordings/gimbal，采用现有 H.264 copy 参数。
它不依赖相机 TF 卡，也没有改动相机内部 SD 卡录像开关、分辨率、帧率或码率。

六、网页关机按钮

增加“关闭板子”按钮，不增加二次确认弹窗。
按钮沿用既有配对会话和页面控制权。
点击后：停止跟随、推进输出归中并请求解除武装 → 停止云台 → 等待当前录像封装完成
→ 返回正在关机状态 → 发送 sudo -n /usr/bin/systemctl poweroff。
模拟测试核对实际命令和调用顺序。为完成本次在线验收，没有在真实板上按下关机按钮。

七、验证记录

1. 修复前完整 Node 测试：490 项，452 通过、38 失败。
2. 修复后完整 Node 测试：500 项，462 通过、38 失败，无新增失败。
   这 38 项旧失败仍存在，涉及既有测试桩/接口和旧坐标预期等，不能宣称全库测试全绿。
3. 本次新增 10 项模拟/集成测试通过，包括：
   − 6 万个 UWB 更新点的 45°/秒和 1 米/秒约束、角度与 XY 一致性；
   − 环绕角、重复时间戳、后方限位、2.5 米控制目标；
   − 300 轮模拟录制进程启停、出错和退出时序；
   − 真实 FFmpeg 生成、封装并探测 5 个 MP4；
   − 隔离生产后端、真实 HTTP/Socket.IO、模拟 A8 UDP、独立 RTSP 源；
   − 模拟关机，不向真实操作系统关机接口发出测试请求。
4. 真机 RTSP：1280×720，25 fps，H.264，has_b_frames=0。
5. 真机网页同一路由录像：连续 6 次成功启停并保存，逐帧解码无报错。
6. 标签上电后：一次 60 样本跟踪记录确认真实云台响应；
   后续 150 样本均有有效 UWB 和姿态反馈，末段 20 样本目标偏航与反馈偏航
   平均绝对差约 2.37°。末样本目标 −96.63°，反馈 −94.2°。
   这是角度反馈对照，不是画面目标中心精度标定，也不是全工况可靠性证明。
7. 维护结束时船体未武装，录像和云台跟踪均停止；服务继续运行。
