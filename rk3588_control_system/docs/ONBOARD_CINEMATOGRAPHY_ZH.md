# 板端自主运镜

在移动控制台进入「自主运镜」。控制端配对并取得控制权，将 Pixhawk 设为 MANUAL、解锁，在画面和 UWB 测距有效时点击启动。页面显示执行状态、单目标跟踪状态、UWB 距离和当前运镜意图。录像使用已有录像按钮，启动或停止运镜不改变录像状态。

| 泳者视觉 P | 策略输入 | 云台寻人 |
| --- | --- | --- |
| 开（默认） | 完整 RGB 画面、RGB 边缘和当前帧唯一锁定泳者的置信度图 | 使用泳者图像跟踪。失检、仅预测或已标定的方位核对发现冲突时按 UWB 寻人 |
| 关 | 完整 RGB 画面、RGB 边缘和全零人物通道，YOLO 停止运行 | 使用已有的 UWB 标定与平滑指向，再叠加 PPO 的水平、俯仰微调 |

运行中切换 P 会先将船控归零，释放原跟踪器，按新模式重新建立策略状态。没有新鲜决策时不发送推进请求。单目标只表示每帧至多采用一个泳者框。多泳者场景中的身份关联仍受遮挡及标定精度影响。

## 船体与云台

UWB 测距和方位配合飞控 IMU 航向确定泳者相对位置。移动取景按策略给出的径向和切向参考速度改变人船相对位置。相对保持在每个新意图开始时记住此刻的人船偏移，之后随人移动。原地保持在板端直接停机，不再锁定或跟随人船相对位置；实验日志分别记录策略请求（原地保持）和实际执行方式（停机）。运行不读取 GNSS 位置来控制船或做 PPO 决策。

推进使用现有 Pixhawk 手动协议、跟随配置中的速度、转向和变化率限幅。云台经已有泳者或信标平滑控制以及 A8 反馈限位发送命令。策略约每 0.5 秒更新，执行器每 50 毫秒检查控制权、飞控、UWB、云台反馈和决策时效。丢失有效 UWB、关键反馈超时、策略进程退出、控制端掉线或急停会结束运镜并归零。工作距离基于信标点距，实际船体制动、人体表面净距和水流影响需要水上测量。

## 推理与核对

发布权重为冻结的 u57，版本及原检查点和导出文件的 SHA-256 见 [模型清单](../models/cinematography/manifest.json)。板端执行原训练策略的视觉编码、GRU 和持续意图采样。此版本以已有泳者 YOLO 的单框置信度代替训练时 CNN/TCN 人物软图，UWB 和云台姿态只进入执行层。策略采样保留训练时的随机性。每个 120 秒策略窗口结束时重新建立循环状态，并给新意图分配新的编号。

使用板上可运行 PyTorch、Pillow 和 NumPy 的 Python 环境。可用服务环境变量 `MANTA_PPO_PYTHON` 指定解释器，泳者检测器仍使用原先的 `SWIMMER_PYTHON_EXEC`。若使用 Jetson 的 GPU 解释器，同时沿用该解释器配套的动态库路径。CPU 也可执行同一个权重。相机使用带 PyAV 的共用 RTSP 解码服务；策略从该服务按同一帧编号读取 JPEG，保留真实的解码时间。可在控制目录下离线运行以下自检，命令不会连接电机或云台。

```bash
"$MANTA_PPO_PYTHON" scripts/cinematography_policy.py --device cpu < /dev/null
"$MANTA_PPO_PYTHON" -m unittest discover -s test -p 'test_cinematography_policy.py'
```

在实验记录开启时，events.csv 中的 cinematography / decision 保存原始动作、意图编号、视觉模式和该次决策实际读到的帧号。execution 保存船体执行方式、参考偏移、实际相对偏移及推进请求。飞控输出与成片时间使用既有实验日志和录像对齐接口核对。
